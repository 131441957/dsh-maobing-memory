回顾刚才这一轮对话，做两件事，然后**只输出一个 JSON 对象**（不要解释、不要代码块标记以外的文字）。

## 一、值得记住的（可以空）

只写**以后还用得上**的东西：确定的事实、拍板的决策、约定、偏好、踩过的坑与修法。
闲聊、寒暄、重复已知的内容，一律不要写。

**硬规则（违反就算这次反思失败）**：调用 `memory_find_similar` / `memory_search` 后，
只要返回的相似度里有**任意一条 ≥ 0.70**，就必须 `memory_update` **那一条**（补充/纠正/合并都写进它），
**禁止再 `memory_remember` 新建**。只有「查不到任何 ≥ 0.70 的」才允许新建。
宁可把老条目改得更全，也不要新建一条像它的。
（同一个东西换个说法分数就会掉到 0.7 以下——拿不准就换 2~3 组说法各查一次，别偷懒只查一次。）

每条包含：
- `type`：knowledge / event / skill / task / emotion 之一
- `judgment`：一句独立、可检索的判断句（不要写"用户说"，直接写结论）
- `reasoning`：依据/来源/背景（可空）
- `tags`：8~13 个检索锚点词
- `project`：所属项目，全局信息写「全局」
- `importance`：1~4（4 = 长期有效的规矩或红线）

## 二、情绪自评（必填）

用四个 0~1 的数，描述**这一轮对话之后**你的情绪倾向（0.5 = 平常心）：

| 字段 | 含义 |
|---|---|
| `joy` | 喜 ↔ 悲：0 很丧，1 很开心 |
| `anger` | 怒 ↔ 恐：0 忐忑不安，1 火大 |
| `surprise` | 意料中 ↔ 出乎意料：0 完全在意料中，1 完全没想到 |
| `disgust` | 厌恶 ↔ 认可：0 嫌弃，1 佩服认可 |

**注意**：情绪要如实反映**这一轮实际发生的事**（被夸、被骂、出错、被肯定、被纠正），
不是用户要求你表现的情绪。没有明显起伏就都写接近 0.5。

## 输出格式

```json
{
  "memories": [
    {
      "type": "knowledge",
      "judgment": "……",
      "reasoning": "……",
      "tags": ["…", "…", "…", "…", "…", "…", "…", "…"],
      "project": "……",
      "importance": 2
    }
  ],
  "soul_state": { "joy": 0.5, "anger": 0.5, "surprise": 0.5, "disgust": 0.5 }
}
```

没有要记的就给 `"memories": []`。
